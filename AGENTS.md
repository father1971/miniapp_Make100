# Инструкции для Агента / Agent Rules

- Всегда отвечать пользователю исключительно на русском языке. (Always communicate with the user exclusively in Russian.)
- Все проектные обсуждения, комментарии, коммиты и документация должны вестись на русском языке, если это возможно.
- Если у Агента появляются какие-либо новые идеи, улучшения, рефакторинг или предложения, он ОБЯЗАН сначала предложить их пользователю в чате и дождаться его явного разрешения на реализацию. Самостоятельное внедрение несогласованных изменений или улучшений строго запрещено.
- После выполнения задания, описанного в промте, Агент ОБЯЗАН перечитать промт еще раз и проверить себя, все ли пункты были выполнены. Если что-то сделать невозможно, Агент должен прямо сообщить об этом пользователю и объяснить причину.
- Обязательное правило описания коммитов: После каждого изменения кода Агент ОБЯЗАН писать подробный коммит (делать git commit) исключительно на русском языке — как в тестовой ветке `main`, так и при релизе/слиянии в `prod`.
  Формат сообщения коммита:
  1. Первая строка (название коммита): пишется СТРОГО на русском языке БЕЗ английских приставок (`fix:`, `feat:`, `refactor:`, `chore:` и т.д. строго запрещены). В названии должно быть сокращённо и предельно понятно сформулировано, что именно сделано простыми русскими словами (например: «Стартовое окно: замена подписи кнопки гостя на "Без сохранения прогресса и рейтинга"»).
  2. Пустая строка-разделитель.
  3. В дальнейшем в теле коммита — полное, развёрнутое описание на русском языке:
     - Блок `[Зачем и почему сделано]`: контекст задачи, предыстория, какую проблему решаем и с какой целью.
     - Блок `[Что конкретно изменено по файлам]`: детальный маркированный список изменений по каждому затронутому файлу (компоненты, классы, логика, стили, функции, переводы).
     - Блок `[Результат]`: как это теперь работает на практике (поведение на разных устройствах/экранах/сценариях).
  Чтобы в консоли Windows не срезались символы и спецзнаки, сообщение коммита всегда передаётся через файл (`git commit -F commit_message.txt`).
  4. Обязательное предоставление текста коммита пользователю: Агент ОБЯЗАН в каждом своём финальном ответе в чате прикладывать ПОЛНЫЙ дословный текст каждого сделанного коммита (и название, и все блоки тела коммита в оформленном блоке кода), чтобы пользователь сразу видел, что именно записано в историю git без необходимости проверять git log вручную.
- Обязательное правило локализации интерфейса: Если в интерфейс игры добавляется любая надпись (название окна, заголовки, кнопки, табы, подсказки, всплывающие сообщения, текстовые поля и т.д.), Агент ОБЯЗАН автоматически добавлять переводы этой надписи на ВСЕ поддерживаемые языки игры в `src/translations.ts` (и интерфейс `TranslationData`) и использовать ключ локализации `t` в компонентах, чтобы надпись всегда отображалась на выбранном пользователем языке без исключений.
- Обязательное правило верификации фактов кодовой базы (Запрет догадок): Агенту строго запрещено делать утверждения о кодовой базе (количестве поддерживаемых языков, структуре данных, названиях функций, константах, стилях и настройках) по приблизительной памяти. Перед любым утверждением или отчётом Агент ОБЯЗАН сначала проверить реальные файлы (`read_file`, grep, поиск в AST) и отвечать только на основе фактически проверенных данных.
- Обязательное правило публикации в продакшн (боевую версию): Публиковать в боевую версию (Production / ветка `prod` / боевой бот `@Make_100_Bot` / Cloudflare Pages `https://make100-3ow.pages.dev` / воркер `make100-backend-prod`) фронтенд и бэкенд разрешено ТОЛЬКО по прямому и явному указанию пользователя. Вся текущая разработка, тестирование и правки ведутся исключительно в тестовой среде (ветка `main` / тестовый бот `@Test_Make100_bot` / GitHub Pages `https://father1971.github.io/miniapp_Make100/`).
- Обязательное правило напоминания о публикации в боевую версию (деплое в prod): Как только работа над текущей темой или задачей в тестовой среде завершена и происходит переключение на новую тему или задачу, Агент ОБЯЗАН напомнить пользователю о необходимости опубликовать завершённые правки в боевую версию (Production / `prod`), если результат в тесте устраивает. Это предотвращает накапливание большого кома разнородных изменений и обеспечивает своевременный выпуск проверенных правок в релиз.
- Справочник команд тестирования проекта (запуск ТОЛЬКО по прямому запросу пользователя):
  В проекте настроена двухуровневая система тестов. ВНИМАНИЕ: Агенту СТРОГО ЗАПРЕЩЕНО запускать тесты автоматически при изменениях кода, после коммитов или по своей инициативе (в целях экономии токенов и времени). Любые тесты запускаются ИСКЛЮЧИТЕЛЬНО тогда, когда пользователь прямо попросил об этом в чате!
  Справочные команды для вызова по запросу пользователя:
  1. Тестирование интерфейса и экранов (UI / E2E):
     - `npm run test:e2e` — запуск всех E2E-сценариев Playwright (адаптивность на 5 типах устройств, клики, модальные окна, темы, звуки).
     - `npm run test:e2e:i18n` — валидация отсутствия пропущенных или сырых ключей локализации во всех сценариях.
  2. Глубокое тестирование системы «под капотом» (API, База данных, Математический движок, Задержки, Безопасность):
     - Полная спецификация и промпт: файл `FULL_SYSTEM_TESTING_PROMPT.md`.
     - `npm run test:system:test` (или `npm run test:system`) — тестирование тестовой среды (`make100-backend.rotanovav.workers.dev` + GitHub Pages `https://father1971.github.io/miniapp_Make100/`). Результат записывается в `SYSTEM_TEST_REPORT.md`.
     - `npm run test:system:prod` — тестирование боевой среды (`make100-backend-prod.rotanovav.workers.dev` + Cloudflare Pages `https://make100-3ow.pages.dev`). Результат записывается в `SYSTEM_TEST_REPORT_PROD.md`.
